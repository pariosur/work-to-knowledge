# Synthetic walkthroughs

These examples contain invented, generic work solely to demonstrate behavior. They are not real results or source claims.

## Coding: duplicate import retries

Selected workspace: an approved sample project. Event c1: the agent considers a request key to prevent repeated imports. No result exists: journal only, no claim of success. Event c2: an actually observed local fixture run (in this hypothetical scenario) repeats a request and creates one row. Event c3: the chosen approach covers repeated keys but not different keys for the same content.

The episode combines a choice, observed narrow evidence and a reusable limit. One debrief covers c1–c3, linking the concept “Idempotency” if an equivalent note already exists. It says the fixture supports repeated-key behavior, not production reliability. A proposed deployment stays proposed. Encountered is the learning status. A PR opening, if observed, can prompt reevaluation but does not imply merge or mastery.

On restart, a prepared record for c1–c3 resumes the same debrief and any missing backlinks. A committed record produces no new debrief. An additional “rename variable” event does not itself qualify. A later observed collision becomes a new episode linking the earlier conclusion.

## Marketing: survey evidence changes a message

Selected topic: audience-research, explicitly established by the user. Event m1: an initial benefit statement is a hypothesis. Event m2: inspected interview excerpts suggest some participants misunderstand the benefit. Event m3: the team chooses a clearer draft and notes that the sample cannot establish conversion lift.

The episode supports a debrief about qualitative evidence and claim limits, not “the campaign increased conversions.” A book-note folder approved read-only contains a relevant passage about sampling limitations. Read and cite the exact section; reuse an existing “Sampling bias” concept even if the source says “selection bias” only when their meanings actually match. If they differ, distinguish them. Create a source companion with a concept backlink; leave the original book note untouched. No relevant passage means no claimed source connection.

With generated roadmap mode, suggest practicing a falsifiable test and checking prerequisite knowledge about measurement; record encountered, not mastered. With roadmap mode none, generate no roadmap. With existing mode, preserve completion checkboxes.

## Exclusions and overrides

A globally configured user excludes personal-health and a confidential workspace. A session in either, a symlink into the excluded workspace, or mixed uncertain context produces no journal or state writes. A selected marketing topic does not override the workspace exclusion. “No record this session” applies even to an otherwise eligible coding task. Unknown workspace/topic context silently skips. A later request to change exclusions updates config; it does not backfill the excluded conversation.

## Repeated-source and crash cases

A second debrief uses a source already linked to a concept: reuse the source companion and existing link, add only the new related-work relationship. If a crash occurs after adding a backlink but before checkpointing it, inspect the existing canonical destination and marker, then complete the checkpoint without appending it again. If an output file conflicts with another episode ID, defer and report a conflict on an explicit status request; never overwrite it.
